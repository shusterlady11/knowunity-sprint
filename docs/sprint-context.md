# Sprint context

Voice-based active recall for Knowunity, a study app.
Web prototype styled as iOS: 390px, dark mode only.

**Concept:** Students speak a concept out loud and Knowie replies in text.

**Where it lives:** A study-plan step (early, and at the end for full review), plus "Explain out loud" in main chat.

## Decisions
- Voice/keyboard toggle on every screen where the student can answer, because switching input shouldn't break the flow. A correct result has none, since there's nothing left to answer (2026-09-29). The chosen mode carries over to the next question until the student switches back.
- OS mic denied: keyboard mode, slashed mic, no micButton, mic side opens re-enable flow, because the mic can't work without permission.
- Primer declined: keyboard mode, mic still selectable, because permission can still be asked.
- "No thanks" on the confirm screen returns to the launching screen, because the student is never trapped. In the usability test, which has no launching screen, it goes to the end screen (2026-09-29).
- Cancel (an X beside the mic while recording) throws away the take and returns to idle, mic ready, because a fumbled start shouldn't force a bad submission, and idle is where the student can record again, switch to keyboard, or skip.
- Prototype purpose (2026-09-29): a usability test with students on a real iPhone in Safari, deployed over HTTPS, in English, on the team's test phones or a remote participant's own iPhone, opened from the Home Screen as a full-screen web app (no Safari toolbars, so the full height holds and there's no back swipe). On phones that aren't 390 wide, the whole 390×844 design scales to the phone's width; iPhone screens share nearly the same proportions, so it also fills the height. The first remote participant has an iPhone 17 (402×874 points): the design scales to 103%, 844 becomes about 870, leaving about 4 spare points. Links carry a short meaningless code (e.g. /s/k7) that maps to a script stored in the prototype, so the student can't read the plan in the address, and the Home Screen icon keeps that code. The moderator talks a remote participant through Add to Home Screen, and watches through the participant's screen share on the call. Each participant gets role-play tasks per question ("answer this fully", "leave something out", "say you don't know") that match the script, so verdicts make sense to them. This replaces the earlier "happy path only" scope.
- Recall engine (2026-09-29): mocked for now; a real engine (Safari speech recognition + an AI judge) is estimated at 3–5 days and deferred. The mock is one piece with a fake setting that a real one can replace later without touching the screens. A script in the link gives each question its own chain of takes, and each take lists the key points it covers (e.g. q1: 1,2 > 3), plus special takes for "didn't catch that", "I don't know" and "slow". The verdict, combined coverage, next hint and covered count are all worked out from the key points, as a real engine's answer would be. What a student does on one question can't shift another's chain: leftover takes are dropped when they move on, and takes beyond the plan cover nothing new. The transcript is canned per question and verdict, and participants are told beforehand that the words shown are placeholders. No real microphone is used: recordingGlow only breathes, with no ripples, so nothing claims to hear the student; the primer screens show but no browser prompt appears, and a denial is only reachable through "Not now".
- Content: 5 questions from what the participants just studied, supplied by the designer. Each has 2–4 key points, a pre-written hint per key point, and a canned transcript for each verdict it can get.
- Missing designs: no answerCard change is needed. The card's text is Knowie's feedback, passed as `message`, and the processing card already shows "Thinking..." ("Taking a moment…" is passed as its `message`). The typing route uses the Figma `chatInput` set (not "Chat Input (legacy)"), with rules in docs/chatinput-decisions.md (2026-09-30). The ToggleGroup + Skip row shows above the bar only while the field is empty; it's hidden while the field has text. Screen margins stay 16px everywhere; a 12px inset was considered and dropped. chatInput, like AnswerCard and ToggleGroup, fills the width the scaffold gives it instead of a hard-coded 358px. Exit confirm, end screen and "Taking a moment…" timing are composed from existing components and reviewed in Storybook.
- Screens in scope: first-run splash and mic permission primer before question 1; question; dictating with cancel; processing; correct, partial, wrong and "didn't catch that" results; Reveal answer sheet; hints; keyboard answering (required, because "Not now" must lead somewhere); Results (perfect and non-perfect); exit confirm; end screen. XP card stays out until its stats exist as a Figma component.
- Question screen content (2026-10-01): placeholder questions in `src/content/` until the real ones exist (was D12). The top of the question screen is Figma's `middleSection` component, built in code, not the question frames' loose layers; its "Welcome!" intro card shows on question 1 only. The mic primer's background uses it too.
- Mic primer text (2026-10-01): a styled Headline S line, not `TextBlock`, since no `TextBlock` size uses Headline S (was D6).
- Exit confirm (2026-10-01): `TextBlock` L ("Leave?", caption "Your progress is saved."), then "Keep going" (Primary) and "Leave" (Secondary). A Secondary button on any sheet fills with `background/floating`, Figma's override on the mic primer, built into `BottomSheet`.
- Dictating hint (2026-10-02): the hint under the question reads "Listening…" when recording starts, then "Tap to submit…" after 3 seconds, so the student first sees the mic is on, then how to finish. It's a timer, since the mic is mocked; recording still stops only on the student's tap. Figma shows "Tap to submit" throughout.
- Entry link (2026-10-02): opened in Safari, `/s/[code]` stays put and shows how to add it to the Home Screen, because iOS Home Screen apps don't share storage with Safari and the icon must keep the code; opened from the icon it goes straight on. "Continue in browser" keeps computer testing possible. The app's home address `/` resumes a session or starts one on the `tour` script (was D5). A different code starts a new session; an unknown code says the link doesn't work.
- Intro card (2026-10-05, replacing 2026-10-04): the "Welcome!" card shows only the very first time the student sees question 1, after the mic primer. It stays until they tap the mic; the dictating screen opens with it and fades it out while the question card slides up, once Knowie is listening, so the change reads as the conversation moving on. Switching to the keyboard or skipping also retires it. "Intro seen" is saved in the session, so it stays gone after a reload or "Review all"; the mic primer's "Turn on" and "Not now" clear it, since they lead to a fresh first question. The splash starts a session if there isn't one, so this is always remembered.
- Result screen (2026-10-04): hints, correct lines and the Reveal answer text are placeholders in `src/content/questions.ts` until the real content exists. `BottomCTA`'s drawer keeps Figma's 28px under its buttons; the 24px bottom-button rule covers plain full-width buttons. The hint is chosen when a take is judged, so reopening a result doesn't use up another.
- Screen corners (2026-10-04): `Scaffold` has square corners in code. Figma rounds its frame to draw the phone, but the iPhone's screen is already rounded, and a second rounding left dark wedges under the Reveal answer sheet and the bottom bar.
- Overlays (2026-10-04): the screen behind a sheet is dimmed by the scrim, not blurred as some Figma frames show, so it stays visible. Sheets with text inset it 32px from the screen edges, and a sheet without buttons leaves at least 32px under its content (more to clear the iPhone's home bar). A sheet grows with its content up to just below the app bar, then its content scrolls. These rules live in the build-screen skill.
- Results (2026-10-05): perfect at 5 correct, mixed at 1–4, "Here's how it went" at 0 (ring hidden, skipped card first, as in Figma). Repeated canned transcripts show once. `tour`'s later pass answers everything, so the perfect state is reachable in a walkthrough.
- End screen (2026-10-05): the way in (finished, left or opted out) is saved in the session by the button that leads to `/done`, not passed in the address, so the message survives reopening the app from the Home Screen. Nothing saved means finished (was D3).
- Typing (2026-10-05): the mic `chatInput` draws in its empty field is hidden on the typing route, since the toggle is the way back to voice and there's no real mic (was D14). After a typed answer, the result screen shows the typing bar instead of the mic; tapping it opens typing with the field focused.
- Mic skipped (2026-10-05): no shadow under Knowie (Figma's is a loose layer; was D8), and the paragraph is `TextBlock` L's Headline XS caption rather than Figma's Headline S, so the screen is built only from components (was D13).
- Build order (2026-09-30): screens are built in flow order, each only after the screen that leads to it, so no button leads to a missing page: splash, mic primer, question, dictating, entry link and reset, processing, result, Results, end screen, typing, mic skipped. This replaces the earlier easiest-first order, which put the end screen and mic skipped before any screen that leads to them.
- Links to unbuilt screens (2026-09-30): every button points to its real route from the start, even before that screen exists; the screen stays unfinished until the route does, rather than pointing somewhere temporary. Screens are built through the build-screen skill (`.claude/skills/build-screen/SKILL.md`), which also sets the rule for missing components: build it inside the screen and log it in `docs/component-gaps.md`; the second screen that needs it turns it into a real component.
- Button margins (2026-10-01): full-width buttons at the bottom of a screen sit 16px from each side, lining up with the cards above, and 24px from the bottom edge, not at the 28px inset some Figma frames use. Found on the first-run splash.
- Centered content (2026-10-01): on screens whose middle content is a centered block, the block sits 24px above the true middle, which looked better on the first-run splash than exact centering. Applies to the End screen and Mic skipped.
- Recording: the student sees no words while speaking, only after stopping, so they recall rather than proofread.
- Processing: "Thinking..." shows for at least 1.2s. A "slow" script entry makes it become "Taking a moment…" after ~4s and fall back to "Didn't catch that" after ~10s, so both states can be tested.
- Retries: a verdict counts all takes for a question combined. On partial or wrong, the answer card's text is the next unused pre-written hint, and its copy includes the covered count ("You've got 2 of 3 key ideas…"). After 2 hints, the card shows one fixed nudge for every question ("You're close. Want to see the full answer?"), with the mic still live. "Reveal answer" is always on the left and stays Tertiary, even after the nudge (2026-10-05; it no longer becomes the primary button). On correct, the card shows that question's correct feedback, written in the content (2026-09-30). Results rows show all takes for a concept joined, so every take is stored.
- Non-answers: an "idk" script entry is treated as Skip ("I don't know"): no result screen, straight to the next question. A question back or off-topic speech would be judged wrong; the mock covers it with a "wrong" entry. Knowie never answers it.
- XP: 10 first-try correct, 5 correct after a hint or retry, 1 revealed, 1 needs practice (Next after a partial or wrong), 0 skipped. A correct retry after a reveal still counts as revealed (1 XP, needs practice), because repeating a shown answer isn't recall. No "say it back" claw-back, since it isn't built. A correct answer reached after a retry without a reveal lands in good explanations. After both hints, the card shows the nudge; "Reveal answer" stays Tertiary on the left (2026-10-05).
- Results (2026-09-29): no results-level Try again round; retrying happens on a question by tapping the mic. The bottom bar is "Review all" + "Continue". "Review all" starts a new pass of all 5 questions; XP carries over, and Results show only the latest pass. Scripts have a first-pass chain and a later-pass chain per question. Continue goes to the end screen, which shows one message for each way in (finished, left, opted out) and offers nothing to tap.
- Leaving: the appBar X opens a confirm sheet ("Leave? Your progress is saved."); Leave goes to the end screen. A reload resumes where the student was, since progress is saved on the phone, except mid-take: reopening on recording or thinking returns to the question and drops that take. A hidden reset link clears everything between participants. The progress bar shows questions finished (0 on question 1), starting at 0 again each pass. Screen readers hear every state change as a full sentence from one hidden live region.
- Processing copy is "Thinking...", because the wait should feel calm and literal.
- Answers show the verbatim transcript, because a paraphrase hides "misheard" vs. "wrong." In the usability-test build it appears only in the Results rows, not on the result screen, whose card holds Knowie's feedback as in Figma (2026-09-30). A typed answer shows exactly what was typed.
- Bottom bar labels are short ("Next", not "Next question"; "Review", not "Review 3 concepts"), because L labels are set in Inter, which is wider than Greed Condensed, and the longer pairs don't fit side by side at 390px.
- Correct: "More info" + "Next", because there's nothing to fix.
- Partial or wrong: "Reveal answer" + "Next" with the mic live, because the student can retry or move on.
- "Didn't catch that": neutral tone, "Reveal answer" + "Skip", because the app misheard, not the student.
- Skip (before first attempt, or after "Didn't catch that") counts as skipped; "Next" after partial or wrong counts as needs practice, because Results separate "didn't try" from "tried and missed."
- "Reveal answer" / "More info" open a bottom sheet (answer, context, X, no buttons), because the student reads, then retries or moves on.
- XP: full unaided, partial hinted, minimal revealed, unaided "say it back" earns some back; streak counts unaided passes only, because XP and streak are the mastery signal.
- Some session XP stays pending until the breakdown shows, because the reward should match the real result. Dropped for the usability-test build, which has no XP card: XP counts up as it's earned (2026-09-29).
- Results: XP card, then concept breakdown, because reward and mistake review shouldn't mix.
- Code uses Inter, not Greed, because Greed is an unlicensed trial font that can't be published; Greed is preferred if licensing is ever cleared.
- Tried switching to the real Greed VF trial font for real (2026-09-28), reverted same day: many already-built components (button, bottomCTA, toggleGroup, appBar, bottomSheetAppBar) were specifically measured and had labels shortened against Inter's wider character metrics, so Greed's narrower rendering broke that fit rather than just "looking more accurate." Re-attempt only alongside re-tuning those components' measurements, not as a drop-in swap.
- Score ring hidden at 0 correct, because results stay encouraging.
- XP card and breakdown copy change with how the student performed (tiers such as perfect, mixed, mostly skipped; more may be added), because feedback should be encouraging and honest about the result.
- recordingGlow's 4 static resting-state rings are retired, replaced outright by the ripple/breathing motion, because static lines carry no information — the motion should move in unison with the speaker's actual voice pattern as real-time feedback, and anything extraneous shouldn't appear.
- recordingGlow in the usability-test build (2026-09-29): the two filled circles breathe per docs/recordingglow-listening-spec.md §3, and the two outline rings are removed. There are no ripples and no real mic level. The blur values (20px, 2px) sit in tokens/motion.json as part of the animation. The rest of that spec (ripples, mic level, ripple color) waits for the full rebuild. Figma doesn't have to match the code's animation exactly, because Figma can't hold motion.

## Not building
- Real speech-to-text or AI judging for now (mocked; see Recall engine)
- Native iOS behavior
- Auto-endpointing (push-to-talk, explicit stop)
- Pause/resume within a take
- Tutoring or open conversation
